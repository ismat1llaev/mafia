# 🎭 Мафия — мини-приложение для Telegram

Онлайн-мафия внутри Telegram: комнаты по коду, автоматическая раздача ролей,
ночные ходы, голосование и подсчёт победы. Обсуждать удобно голосом в звонке
Telegram, а все механики берёт на себя приложение.

**Роли:** мафия, доктор, комиссар, мирные жители.
**Игроков:** от 5 до 12.
**Ведущий:** бот (все играют) или живой человек — выбирается при создании комнаты.
**Играть одному:** кнопка «Играть с ботами» на главной — стол собирается сам, партия начинается сразу.

---

## Что нужно перед стартом

1. Бот, созданный у [@BotFather](https://t.me/BotFather) — у вас это `@MafiaGameGGbot`.
2. Его **токен** (`/mybots` → ваш бот → *API Token*).
3. Аккаунт на [Render](https://render.com) — хватает бесплатного плана.
4. Аккаунт на GitHub — Render забирает код оттуда.

> **Почему Render.** Игре нужен процесс, который живёт постоянно: он держит
> WebSocket-соединения со всеми игроками и хранит комнаты в памяти. Vercel,
> Netlify и подобные бессерверные площадки так не умеют — там функция
> просыпается на один запрос и умирает. Render даёт обычный сервер
> с WebSocket и бесплатным HTTPS-адресом.


`.gitignore` уже настроен: `node_modules`, `dist`, `data` и `.env`

задаётся переменной окружения на самом Render.

## Шаг 2. Создать сервис на Render

В корне проекта лежит `render.yaml` — он описывает сервис целиком,
поэтому форму заполнять почти не придётся.

1. Зайдите на [dashboard.render.com](https://dashboard.render.com).
2. **New** → **Blueprint** → подключите свой GitHub и выберите репозиторий.
3. Render прочитает `render.yaml` и покажет один сервис `mafia`.
   Он спросит значения переменных, которые не хранятся в git:

| Переменная       | Что вписать                                          |
|------------------|------------------------------------------------------|
| `BOT_TOKEN`      | токен от @BotFather                                  |
| `BOT_USERNAME`   | `MafiaGameGGbot` (без `@`)                           |
| `CHANNEL_URL`    | необязательно: канал проекта, например `@MafiaNews`  |
| `CHANNEL_ID`     | необязательно: куда публиковать посты                |

   `WEBHOOK_SECRET` Render придумает сам, `BOT_MODE=webhook` и `PORT`
   уже проставлены.

4. **Apply** — пойдёт сборка. Первая занимает 2–4 минуты.

Адрес вида `https://mafia-xxxx.onrender.com` появится вверху страницы сервиса.
**Вписывать его в переменные не нужно**: Render сам отдаёт приложению
`RENDER_EXTERNAL_URL`, а сервер её подхватывает.

В логах (вкладка **Logs**) должно появиться:

```
[server] слушает 0.0.0.0:10000
[bot] команды и кнопка меню настроены
[bot] вебхук установлен: https://…/webhook/…
```

Три строки на месте — сервер работает. Откройте
`https://ваш-адрес.onrender.com/health`, там должен быть `{"ok":true,…}`.

> **Если не хотите пользоваться Blueprint**, можно завести сервис руками:
> **New** → **Web Service** → репозиторий → Runtime `Node`,
> Build Command `npm ci`, Start Command `npm start`, план `Free`.
> Переменные из таблицы выше плюс `BOT_MODE=webhook` и `WEBHOOK_SECRET`
> (любая случайная строка из букв, цифр, `-` и `_`) добавьте вручную.

### Автосборка после пуша

Сервис подключён к репозиторию по публичной ссылке, поэтому Render сам
новые коммиты не замечает. Сборку запускает GitHub: задача
`.github/workflows/deploy.yml` после каждого пуша в `main` дёргает
Deploy Hook сервиса.

Один раз нужно положить эту ссылку в секрет репозитория:

1. Render → сервис → **Settings** → **Deploy Hook** → скопировать ссылку.
2. GitHub → репозиторий → **Settings** → **Secrets and variables** →
   **Actions** → **New repository secret**: имя `RENDER_DEPLOY_HOOK_URL`,
   значение — скопированная ссылка.

Проверить: вкладка **Actions** → задача **deploy** → **Run workflow**.
В журнале задачи должен быть ответ Render с кодом 200.

### Про бесплатный план

Честно о его двух особенностях — обе решаемы:

**Сервис засыпает после 15 минут без запросов.** Первый запрос после сна
поднимает его примерно за минуту: человек нажмёт кнопку в боте и будет
ждать. Комнаты, которые были в памяти, при этом пропадут.

Лечится внешним пингом: заведите бесплатное задание на
[cron-job.org](https://cron-job.org) или [UptimeRobot](https://uptimerobot.com),
которое раз в 10 минут дёргает `https://ваш-адрес.onrender.com/health`.
Круглосуточная работа — это 730 часов в месяц, а бесплатный план даёт 750,
так что одного такого сервиса хватает впритык.

**Диска нет, файлы живут до перезапуска.** Статистика из `DB_PATH`
обнуляется при каждом деплое и после сна. На саму игру это не влияет —
партии и так живут в памяти. Если статистику хочется сохранить, нужен
платный план с диском (Disk) и `DB_PATH=/data/stats.json`.

## Переезд с Railway

Если игра уже крутится на Railway, порядок такой — старый сервис
выключаем **последним**, когда новый точно работает.

1. **Поднимите Render** по шагам 1–2 выше. Получится второй, параллельно
   работающий адрес `https://mafia-xxxx.onrender.com`.

2. **Проверьте его напрямую**: откройте `https://mafia-xxxx.onrender.com/health`.
   Должен быть ответ `{"ok":true,…}` с правильной версией.

3. **Отключите старый сервис на Railway.** В Railway → сервис → **Settings**
   → **Remove Service** (или хотя бы Pause).

   Это важно сделать до следующего шага. Оба сервиса при запуске
   прописывают вебхук себе, и пока живы оба, Telegram будет слать
   сообщения тому, кто прописался последним — бот начнёт отвечать
   через раз.

4. **Перезапустите сервис на Render** (**Manual Deploy** → **Restart service**),
   чтобы он заново прописал вебхук уже на себя. В логах появится
   `[bot] вебхук установлен: https://mafia-xxxx.onrender.com/webhook/…`

5. **Обновите адрес у @BotFather** — старый `up.railway.app` остался
   в двух местах:
   - `/myapps` → ваш мини-апп → **Edit Web App URL** → новый адрес
   - кнопку меню бот переставляет себе сам при старте, руками не нужно

6. **Проверьте в Telegram**: `/start` у бота, кнопка меню, создание комнаты.

7. **Настройте пинг**, чтобы сервис не засыпал (см. «Про бесплатный план»).

Данные переносить не нужно: комнаты живут в памяти и так, а статистика
на бесплатном плане всё равно не хранится.

## Локальный запуск (необязательно)

```bash
npm install
cp .env.example .env      # впишите BOT_TOKEN
npm run dev
```

Сервер поднимется на `http://localhost:3000`, фронт на `http://localhost:5173`.

Чтобы Telegram видел локальный сервер, пробросьте его наружу:

```bash
npx localtunnel --port 3000
```

Полученный HTTPS-адрес впишите в `.env` как `PUBLIC_URL` и перезапустите.
Для отладки прямо в браузере, без Telegram, поставьте `ALLOW_DEV_AUTH=true` —
но **никогда не включайте это на боевом сервере**: с ним кто угодно может
зайти под любым именем.

Тесты игровой логики:

```bash
npm test
```

мафия, нельзя.

## Настройки комнаты

Создатель комнаты может поменять перед стартом:

- **Ведущий** — бот (все играют) или вы (роли не получаете, переключаете фазы вручную).
- **Доктор** — включён по умолчанию. Ночью спасает одного игрока: если мафия
  пришла именно за ним, он выживает. Лечить одного и того же две ночи подряд
  нельзя, себя — можно. Город не узнаёт о спасении: утром объявляется просто
  «этой ночью никто не погиб», ровно как если бы мафия промахнулась.
- **Комиссар** — выключен по умолчанию, включается по желанию комнаты.
- **Максимум игроков** — от 5 до 12.
- **При равенстве голосов** — второй тур между лидерами, никто не выбывает, или жребий.
- **Длительность фаз** — ночь, обсуждение, голосование (только в режиме бота).
- **Открывать роль выбывших** — показывать ли, кем был погибший.

Состав ролей считается автоматически: мафии примерно треть от числа игроков
(5 → 1, 6–8 → 2, 9–11 → 3, 12 → 4), доктор и комиссар — по одному, если
включены, остальные — мирные. Если особых ролей окажется столько, что мирных
не останется совсем, лишние отключатся сами.

## Автопубликация в канал

Сервер сам выкладывает посты в ваш Telegram-канал по расписанию. Запас
готовых постов лежит в `content/posts.js` — правила, разборы ролей, советы.

**Подключение**

1. Добавьте `@MafiaGameGGbot` в администраторы канала с правом публикации.
2. Задайте на Render (**Environment**) переменные:
   - `CHANNEL_ID` — `@имя_канала` или числовой id `-100…` для приватного
   - `CHANNEL_URL` — тот же канал, включает кнопку «Подписаться» в игре
   - `POST_EVERY_DAYS` — раз в сколько дней постить (по умолчанию 2)
   - `POST_HOUR_UTC` — час публикации по UTC (8 = полдень в Самаре)
3. Перезапустите сервис. В логах появится строка `[канал] автопубликация…`.

Без `CHANNEL_ID` автопубликация просто выключена, всё остальное работает.

**Отдельный бот для канала**

По умолчанию посты выходят от игрового бота. Если хочется, чтобы у канала
был свой автор — со своим именем и аватаркой, — создайте второго бота
у @BotFather и задайте переменную `CHANNEL_BOT_TOKEN`.

Тогда публикацией и командами `/kanal`, `/postnow` и прочими займётся он,
а игровой бот останется только игровым. Администратором канала в этом случае
нужно сделать именно бота канала.

Оба бота живут в одном процессе и слушают разные адреса вебхука, поэтому
дополнительный сервис на Render создавать не нужно.

**Управление из чата с ботом** — команды видят только администраторы канала,
отдельного списка владельцев вести не нужно:

- `/kanal` — сколько постов осталось и когда выйдет следующий
- `/postnow` — опубликовать следующий немедленно
- `/pause` и `/resume` — приостановить и продолжить
- `/addpost` — добавить свой пост в конец очереди

**Как это не ломается**

Состояние очереди хранится вместе со статистикой, а «день последней
публикации» сравнивается по UTC. Поэтому перезапуск сервера посреди дня
не приводит к повторной отправке того же поста. Если сервер пролежал
несколько дней, пропущенный пост выйдет при первом же запуске, а не
потеряется. Очередь сдвигается только после успешной отправки: сбой на
стороне Telegram означает повтор попытки, а не пропуск поста.

## Как открывать мини-приложение

Данные для входа Telegram передаёт **не при всяком способе запуска**.
Их получают inline-кнопки в сообщениях (`InlineKeyboard.webApp`), кнопка меню
рядом с полем ввода и прямые ссылки `t.me/бот/приложение`.

А вот кнопки обычной клавиатуры под полем ввода (`Keyboard.webApp`) открывают
приложение **без данных пользователя** — на уровне протокола это другой тип
кнопки, `keyboardButtonSimpleWebView`. Вход через неё подтвердить невозможно,
поэтому такие кнопки в проекте не используются.

## Два языка

В правом верхнем углу переключатель **RUS / ENG**. Выбор запоминается
в браузере, а при первом входе язык берётся из настроек Telegram: русский
для русскоязычных, английский для остальных.

Устройство перевода: сервер **не присылает готовых фраз**. В журнале партии
и в ошибках едут коды событий и данные — `killed` с именем и ролью, —
а текст собирает приложение на выбранном языке. Иначе половина игры
осталась бы русской при любом переключателе.

Словари лежат в `client/src/dict.js` и не зависят ни от React, ни от
Telegram — поэтому проверяются обычными тестами. `server/i18n.test.js`
читает исходники сервера, собирает все коды ошибок и событий и требует,
чтобы для каждого нашлась фраза на обоих языках. Добавить на сервере новый
код и забыть про перевод не получится: тест упадёт.

## Открытые комнаты

На главной показывается список комнат, куда можно зайти прямо сейчас, —
чтобы играть можно было не только со своими, но и с незнакомыми людьми.

В список попадают комнаты, которые ещё в лобби, помечены открытыми, не
заполнены и в которых есть хоть кто-то живой. Первыми идут почти собранные:
им не хватает пары человек, и зашедший начнёт играть быстрее всего.

Создатель может закрыть комнату переключателем **«Открытая комната»** —
тогда войти получится только по коду.

## Игра с ботами

На главной есть кнопка **«Играть с ботами»**. Она сразу создаёт закрытую
комнату, сажает за стол ботов и начинает партию — ждать живых игроков не нужно.
По умолчанию за столом семеро: вы и шесть ботов. Число меняется переменной
`SOLO_PLAYERS` (от 5 до 12).

Ботов можно подмешивать и в обычную комнату: в лобби у создателя есть панель
**«Боты»** с кнопками «добавить» и «убрать». Так собирается партия, когда
живых игроков пришло меньше пяти.

Бот — обычный игрок за столом: он получает роль наравне со всеми, стреляет,
лечит, проверяет, обсуждает и голосует, и его самого можно убить или выгнать
голосованием. Отличается только тем, что ходы за него делает сервер.

Как бот решает:

- **Мафия** — сначала смотрит, на ком уже сошлись напарники, чтобы выстрел не
  «размазался» по разным целям; при прочих равных убирает тех, кто вчера
  голосовал против мафии. По своим не стреляет никогда.
- **Комиссар** — проверяет тех, кого ещё не проверял, и на голосовании ведёт
  за найденной мафией.
- **Доктор** — лечит кого-то из живых, себя примерно в четверти случаев,
  одного и того же две ночи подряд не лечит.
- **Днём** — боты подхватывают лидера голосования (мафия охотнее, чтобы увести
  подозрение от себя), изредка воздерживаются и бросают пару реплик в чат.

Ходят они не мгновенно: у каждого своя задержка, поэтому фаза не схлопывается
в ту же секунду. Под конец фазы бот перестаёт тянуть, чтобы партия не вставала
на таймере.

Реплики ботов передаются кодом, а не готовым текстом, — поэтому в русской
и английской версии бот говорит на языке игрока. В статистику игроков боты
не попадают: очки начисляются только людям.

## Удостоверение игрока

В левом верхнем углу у каждого игрока — значок-удостоверение. Нажатие
открывает карточку в стиле «Mafia Identification Card»: фото, имя, фамилия,
возраст и пол. За столом, в лобби и в чате игрок стоит под именем и с фото
из удостоверения; пока карточка не заполнена, берутся имя и фото из Telegram.

- Возраст и пол видит только сам игрок — в состояние комнаты уходят лишь
  имя и фото.
- Фото обрезается под рамку 4:5 и ужимается прямо в телефоне до нескольких
  десятков килобайт, EXIF и геометка при этом пропадают. Сервер принимает
  только JPEG и раздаёт снимок по адресу `/api/photo/<хеш>.jpg`.
- Посреди партии имя и фото за столом не меняются — иначе можно было бы
  переименоваться прямо во время голосования. Новые встают на место, когда
  комната возвращается в лобби.

**Где хранится.** На устройстве игрока и в облаке Telegram (CloudStorage),
а не на диске сервера: бесплатный Render стирает диск при каждом перезапуске.
Приложение присылает удостоверение при каждом входе, поэтому после
перезапуска сервера всё восстанавливается само.

## Заставка

При запуске мини-приложения — кнопкой «Играть» в боте — первой показывается
картинка «Welcome to the Mafia» (`client/src/welcome.jpg`). Она держится
около двух секунд, а если сервер ещё просыпается — до подключения. Чтобы
сменить картинку, положите другой файл под тем же именем.

## Обрыв связи

Место в комнате закреплено за игроком, а не за соединением. Блокировка
экрана, входящий звонок, переключение приложений — всё это рвёт связь на
несколько секунд, и выбрасывать за это из комнаты нельзя.

- В идущей партии игрок остаётся в игре, сколько бы ни длился обрыв. Он
  вернётся на своё место со своей ролью.
- В лобби место держится три минуты, потом освобождается для других.
- Код комнаты запоминается в браузере, поэтому даже полная перезагрузка
  приложения возвращает игрока в его комнату, а не в главное меню.

## Правила в личке

При первом входе в комнату бот присылает игроку правила и закрепляет
сообщение в чате — чтобы посреди партии не искать, кто что умеет.
Отправляется один раз на игрока. Если человек ещё не нажимал Start у бота,
Telegram не даст ему написать — тогда попытка повторится при следующем входе.

## Если что-то не работает

**Кнопка есть, но приложение не открывается.**
Проверьте `PUBLIC_URL`: он должен начинаться с `https://` и не заканчиваться слэшем.
Откройте `PUBLIC_URL/health` в браузере — должно вернуться `{"ok":true,...}`.

**Приложение пишет «Не удалось подтвердить вход».**
`BOT_TOKEN` на сервере не совпадает с ботом, из которого вы открыли приложение.
Проверьте, что токен скопирован целиком, без пробелов.

**Бот не отвечает на команды.**
Посмотрите логи: строка `[bot] вебхук установлен` должна быть без ошибки.
Убедитесь, что `WEBHOOK_SECRET` состоит только из букв, цифр, `-` и `_`.

**Игроков выкидывает из комнаты.**
На бесплатном плане Render сервис засыпает после 15 минут простоя, и комнаты
из памяти пропадают. Настройте пинг `/health` раз в 10 минут (см. «Про
бесплатный план») — сервис не заснёт.

**Приложение открывается почти минуту.**
Это просыпается уснувший сервис. Тот же пинг лечит и это.

**Статистика обнуляется после передеплоя.**
Так и есть: на бесплатном плане диска нет. Нужен платный план — добавьте
**Disk**, смонтируйте в `/data` и поставьте `DB_PATH=/data/stats.json`.

Сервер сам замечает эту ситуацию: если файл статистики лежит внутри папки
приложения, при запуске в логах появляется предупреждение, а команда
`/users` дописывает к цифрам оговорку, что они скоро обнулятся.

## Сколько людей пользуются ботом

Команда `/users` в игровом боте показывает аудиторию: сколько всего людей
открывали бота, сколько из них доиграли хотя бы партию, сколько заходили
сегодня, за неделю и за месяц, сколько новых.

Считается каждый, кто нажал «Старт» или зашёл в комнату, — а не только те,
кто доиграл до конца.

Команда доступна владельцу. Владельцем считается тот, чей id указан
в переменной `OWNER_ID`, либо любой администратор подключённого канала —
так настройка не нужна вовсе. Узнать свой id можно командой `/myid`.

## Что можно добавить дальше

Движок написан так, чтобы новые роли добавлялись без переписывания:
в `server/game.js` есть перечисление `ROLE`, функция `roleComposition`
и обработка ночных ходов в `submitNightAction` / `resolveNight`.

Напрашивающиеся расширения: дон (ищет комиссара), маньяк (третья сторона),
любовница (блокирует ночной ход), последнее слово перед казнью, рейтинг
по сезонам.

Ботов тоже можно усложнять, не трогая движок: вся их «голова» лежит в
`server/bots.js` и общается с игрой через те же ходы, что и человек.
